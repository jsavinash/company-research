# Extended and Custom Requirements

## 1. Extended requirements

| ID | Requirement | Rationale |
|---|---|---|
| EX-1 | Multi-category reuse (Frozen → Coffee → Baking) | Amortize platform cost |
| EX-2 | Multi-language / multi-region (future) | Global reuse |
| EX-3 | Custom scenario templates per team | Planner productivity |
| EX-4 | White-label / OEM for retailer collaboration | Partner integration |
| EX-5 | Advanced what-if (price elasticity, promo lift) | RGM depth |
| EX-6 | Anomaly detection on data feeds | Data quality |
| EX-7 | Model registry + lineage UI | Governance |
| EX-8 | Self-serve onboarding | Scale |

## 2. Custom requirements (Nestlé-specific)

| ID | Requirement | Rationale |
|---|---|---|
| CU-1 | Retailer-contract-aware retrieval | Legal compliance |
| CU-2 | GLP-1 prevalence integration (DMA/income) | Regime modeling |
| CU-3 | Panel-data aggregation with minimum cell sizes | Privacy |
| CU-4 | RIG / value reporting to finance | Business case |
| CU-5 | Microsoft Entra ID + Fabric integration | Enterprise standard |
| CU-6 | SAP/Salesforce/ServiceNow integration via MCP | Legacy integration |

## 3. Prioritization

| Requirement | Priority |
|---|---|
| EX-1 (multi-category) | Should |
| EX-3 (templates) | Should |
| EX-5 (elasticity) | Could |
| EX-7 (model registry UI) | Should |
| CU-1..CU-6 | Must (compliance/integration) |

## 4. Acceptance

- Extended requirements validated in respective phases.
- Custom requirements verified against Nestlé-specific constraints (contract, privacy, RIG).

## 5. Change control

New custom requirements require a decision-log entry and impact assessment.
